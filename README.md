# ANIDLE UI в prjhex

React + TypeScript + Tailwind + Vite. Интерфейс перенесён из ANIDLE; данные и сравнение используются из prjhex.

## Запуск

```powershell
npm ci
npm run dev
```

Открой адрес из терминала (обычно http://127.0.0.1:5173).

```powershell
npm test
npm run build
npm run preview
```

## Откуда данные

В этом репозитории нет серверного API. Единственный сетевой запрос нового клиента загружает `data/characters-full.json` с текущего сайта. `src/api.ts` адаптирует эти данные к интерфейсу React и использует сравнение из `js/columns.js`. Нет обращений к localhost:3001, PostgreSQL или серверу ANIDLE.

Доступен One Piece. Темы/компоненты других миров перенесены, но не предлагаются в выборе, пока у них нет каталога. Данные Naruto и его серверный curated-список не переносились. Существующие data/, parser/ и js/ сохранены.

Партии случайные, как в ANIDLE; ежедневный daily.json сохранён, но новый UI его не использует. Подсказка дебюта после 5 неверных попыток, сдача после 10. Данные партии и статистика хранятся в localStorage с префиксом prjhex-ui, отдельно от старой версии. Поскольку это статическая игра, скрытый ответ доступен через инструменты браузера; серверной защиты ответа нет.

Чтобы подключить настоящий backend в будущем, нужно заменить адаптер src/api.ts под его реальные маршруты и схемы. URL такого backend сейчас в проекте отсутствует.

## GitHub Pages

Workflow устанавливает зависимости, собирает приложение с VITE_BASE_PATH=/prjhex/ и публикует dist. Он запускается после push в main или вручную. Ветка feat/anidle-frontend предназначена для проверки и Pull Request. При другом имени репозитория или собственном домене нужно изменить VITE_BASE_PATH.

Старые profile.html и how-to-play.html также копируются в dist вместе с их ресурсами. Они используют старую статистику; новая игровая статистика показана в React-интерфейсе.
